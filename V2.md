# SetupVibe 2

SetupVibe 2 is being developed on the `v2` branch. It replaces the four
scripts (`desktop.sh`, `server.sh`, `omarchy.sh` and `desktop.ps1`) with two
Bun binaries built on the [Termfy](https://github.com/promovaweb/termfy)
framework. Each binary has a TUI, a CLI and an MCP server in the same
executable.

| Binary | Edition | Systems |
| --- | --- | --- |
| `setupvibe` | Desktop: development environment, local or remote | macOS, Ubuntu, Debian, Mint, Zorin, Arch, Omarchy, Windows, WSL |
| `setupvibe-server` | Server: Docker Swarm infrastructure | Ubuntu, Debian |

The specification lives in the ClickUp document "SetupVibe 2". On this branch the SetupVibe 1
scripts, with `conf/`, `bin/`, `utils/` and their docs, already live in
`legacy/` with a notice about SetupVibe 2; `main` and the public addresses
keep serving SetupVibe 1 until the launch (see `legacy/README.md`).

because only one of them is installed on a machine.

## Commands

```bash
bun install
bun run desktop -- --help          # run setupvibe from source
bun run server -- --help           # run setupvibe-server from source
bun test                           # every test
bun run typecheck
bun run build                      # dist/setupvibe and dist/setupvibe-server
bun run build:all                  # every platform
bun run validate                   # typecheck, tests and build
bun run coverage                   # unit test coverage; fails below 88% of lines or 85% of functions
bun run release:assets             # every binary, dist/SHA256SUMS and dist/sbom.cdx.json
bun run inventory:bump             # newer versions (--write to apply, --pr to open a pull request)
bun run inventory:health           # keys, archives and installers still match
bun run state:schemas              # publish shared/schemas/*.schema.json from shared/state/schemas.ts
```

## Container tests

`scripts/container-test.ts` follows the systemd container recipe in
`DEBIAN.md`: it builds the image, copies `dist/<bin>` in, runs `auto`, runs it
again to prove that nothing fails on a second run, and runs `check`:

```bash
bun run build
bun run scripts/container-test.ts --system debian:13
bun run scripts/container-test.ts --system archlinux:latest
bun run scripts/container-test.ts --system ubuntu:24.04 --edition server --as-root
```

`--as-root` starts as root with `--user deploy`, the flow of a fresh VPS.
`--keep` leaves the container running for inspection. CI runs the same
matrix on Debian 12 and 13, Ubuntu 24.04, Mint 22 and Arch. Zorin has no official
container image, so it is covered by the Ubuntu base it shares.

## Rules

- Code, identifiers, messages and JSON keys are in English. Documentation for
  people follows the repository languages.
- Every URL that points at a SetupVibe file uses the `v2` branch through
  `shared/repo.ts`. A test fails when a v2 source file points at `main` or at
  a SetupVibe 1 tag.
- The inventory files are edited by hand and validated by
  `bun test shared/tests` (see `shared/docs/inventory.md`).
- Pre-releases of the branch are tagged `v2.0.0-dev.N`.
